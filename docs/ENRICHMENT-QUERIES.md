## The three queries an ASK screen needs

**1. Find the entity** — match name or alias, case-insensitive:

```sql
SELECT DISTINCT e.id, e.name, e.kind, e.summary, e.first_seen, e.last_seen
FROM entity e
LEFT JOIN entity_alias a ON a.entity_id = e.id
WHERE lower(e.name) = lower(:q) OR lower(a.alias) = lower(:q)
ORDER BY e.mention_count DESC;
```

For fuzzy matching use `LIKE '%' || :q || '%'` on the same two columns, but rank
exact matches first — `PS` is both an entity and a substring of half the corpus.

**2. The facts, grouped and dated:**

```sql
SELECT id, category, fact, asserted_on
FROM entity_fact
WHERE entity_id = :id
ORDER BY category, asserted_on;
```

`category` is one of `access`, `contents`, `location`, `handling`, `history`.
`asserted_on` is `YYYY-MM-DD` and **may be null**.

**Two facts in the same category may contradict each other. That is deliberate.**
Doris has both "there were no ladders" (2022-08-19) and "at least three ladders"
(2022-08-24). Show both with their dates. Do not pick the newer one, do not
de-duplicate, do not hide one behind a disclosure. The camp never resolved it and
the app must not pretend otherwise.

**3. The receipts for one fact:**

```sql
SELECT ev.quote, pc.timestamp, p.name AS said_by
FROM evidence ev
JOIN person_content pc ON pc.id = ev.source_id AND ev.source_table = 'person_content'
LEFT JOIN person p ON p.id = pc.person_id
WHERE ev.claim_table = 'entity_fact' AND ev.claim_id = :fact_id;
```

Every fact has at least one. The quote is copied verbatim from the message at
build time and verified against it — it is reproducible, not paraphrased. Tap to
expand is the obvious treatment; what matters is that it is reachable, because it
is what makes the app trustworthy when someone is deciding whether to walk across
camp.

## Notes that will save you time

- **`entity.summary` is empty for exactly one entity** (`Noah's Ark`) — no
  messages survived the name filter. Handle the empty string.
- **Aliases are noisy in places.** `Doris` carries `Oris`, a typo the discovery
  pass captured. Harmless in matching, slightly odd if displayed. Consider showing
  aliases only when they differ from the query.
- **Facts are written in first person plural** — "we meet her driver", "our bike
  fleet". That is deliberate: Lucy belongs to the camp. Match it in any UI copy
  you write, and never rephrase a quote into that voice.
- **`mention_count` counts chunks, not mentions.** Fine for ranking, wrong if
  displayed as a number.
- The database is regenerated by `scripts/package_db.py --install`. Never copy it
  into the bundle by hand — a manual `cp` is how a dimension mismatch shipped.
